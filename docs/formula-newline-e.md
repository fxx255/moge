# 换行后的 e 被显示为不等号（2026-10-29）

用户提供的错误图样应为 `e=0000010`，界面却显示 `≠=0000010`。
可复现路径是合法 JSON 字符串中的换行 `\n` 后直接跟变量 `e=`，形成原始字符
`\ne=`。客户端为容错模型未转义的 LaTeX，优先将 `\ne` 保留为不等号命令，
因此完整解析和流式解析都改变了原本的变量。旧实现的两个复现测试均失败。

现在两条 JSON 解码路径共用赋值歧义判别：单反斜杠的 `\ne` 后紧接等号
（允许中间有空格）时，按换行和变量 e 解码。流式在等号到达前保留待定状态，
跨分片的结果一致；截断恢复、简明答案字段与重置复用也覆盖此规则。
显式双反斜杠仍按 JSON 规则还原，正常的 `x\ne 0`、`x\neq e`、`\nu=2`、
`\nabla f` 和 `x\notin A` 保留。

为兼容已保存的受损正文，显示准备阶段还修复公式开头的 `\ne=`，保留 e 和等号。
该规则只作用于公式开头，避开代码、缩进代码、公式中的正常关系及文本参数；
不改写历史数据库。原生图像测试检查纸张与黑板颜色下，完成、流式和旧记录的公式
源码及公式选择复制均为 `e=0000010`，译码结果 `c=y+e=0110010` 保留。
