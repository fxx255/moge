# 墨格 0.2.5 · 回答滚动显示修复报告

日期：2026-10-03。版本：0.2.5，versionCode 7。

## 问题与本地复现

用户报告同一对话有两条回答时，上下滑动可能使其中一条只剩首字或首字母，再次滑动后恢复。

正文内容由原生 TextView 渲染，列表由 Compose LazyColumn 布局。原实现先创建空 TextView，等待 onSizeChanged 回调获得宽度后再填入内容，并在后续一帧请求重新测量。这使列表首次放置或预先测量回答时可能得到空文本的一行高度，而实际正文已是多行；裁切区域与正文布局可能暂时不一致。

新增的真实 Compose / AndroidView 回归测试在修改前复现首次测量异常：测试样例稳定高度为 1651 像素，首次放置仅分到 41 像素。测试分别记录首次放置高度与稳定后的原生高度，旧实现断言失败，修复后通过。进一步使用 Android 原生字形测量验证，完成回答首次与稳定高度均为 1660 像素（71 行），流式尾段首次与稳定高度均为 1943 像素（97 行）。该证据确认本地测量时序问题；目前没有连接用户设备，尚未直接复现设备上“只剩首字”的画面。

## 实现

完成回答与流式正文通过 BoxWithConstraints 在创建原生 View 前取得实际可用宽度，factory 立即填入正文，随后由 AndroidView 正常测量高度。内容与宽度变化仍通过 update 更新，保留原有正文缓存及陈旧文本校验。

正文在首次测量前已经就绪，不再依赖首次尺寸回调和下一帧 requestLayout。气泡高度由内容自然决定，公式与表格的异步布局请求仍可正常更新正文和后续内容的位置。主题、字体缩放及是否允许选字变化时，原生组件按其显示属性重建。

## 回归范围

- 完成回答首次放置就取得完整高度。
- 流式尾段在首次放置前填入完整的当前文本。
- 两条中文、英文长回答反复离屏、返回，并用真实触摸上下滑动，校验全文末尾、排版宽度、行数、气泡高度与原生滚动偏移。
- 正文变长、变短与窗口宽度变化后，原生排版与 Compose 高度保持一致。
- 现有异步公式尺寸增减、图片点击、表格横向拖动、选字、字体与主题切换和解答展开动画回归。
