# 题目图像预处理

设置中的“题目图像预处理”默认开启；开启后，进入解题照片裁剪界面即复制一份不可变原图，并登记后台净化任务，不检测是否为题目。裁剪界面不等待净化；对话模式直接跳过，历史图片不做迁移或批量重处理。

当前流程：导入/拍照 → 裁剪期间后台净化不可变副本 → 确认时优先裁剪并原子保存原图，立即交接附件 → 应用作用域随后等待副本、计算最终版本并将裁剪/旋转参数登记到 WorkManager → 后台复用副本净化结果，执行同样的裁剪/旋转 → 原子保存独立 PNG → 已发送照片与查看器自动替换显示。确认只等待原图裁剪保存，不等待副本、指纹计算、设置读取或任务登记；发送也不等待后台任务。净化未完成或失败时继续显示裁剪后的原图。模型请求、上下文和重试始终使用裁剪后的原图，不读取净化文件。

`BookPageProcessor` 已移除自动书页展平、透视和边界校正入口，只保留 `ColorDocumentEnhancer` 的颜色、背景与阴影净化。手动裁剪/旋转继续保留；原始分辨率与无损 PNG 保存不变。净化全程在本机执行，不请求模型或网络服务。原生库加载失败、内存不足或保存失败保留原文件；取消异常继续抛出。

任务注册及原图保存由应用作用域持有，离开页面不取消；WorkManager 持久化已注册任务以便进程重启后恢复。相同路径与相同内容使用唯一任务；接受裁剪时先登记内存交接令牌，常规附件入队等待该令牌完成，避免抢占携带副本参数的任务登记。这个等待属于后台任务，不阻塞裁剪确认或发送。每次重裁替换交接令牌，过时交接不登记新照片的错误裁剪参数。若进程在 WorkManager 登记前终止，恢复草稿时按现有入口重新登记裁剪原图，失去副本复用时回退正常净化。

原生净化通过互斥锁串行执行，`PhotoWorkPriority` 在确认期间阻止副本继续复制或开始新的后台处理阶段；已经运行的原生调用在返回后的检查点让路，原尺寸净化在每 96 行条带之间检查。确认不等待正在运行的原生调用结束，也不强制中断原生代码。复制期间打开的原图流保留被原子替换前的版本；仅打开文件与确认共享短锁，复制与 WorkManager 登记不持锁。复制时同时计算 SHA-256，省去再读一遍副本。确认早于副本打开时不再复制，后续直接净化最终裁剪原图。

已经完成的副本结果直接复用，不在每次拖动裁剪框时重做净化；原图与净化图共用 `PhotoCropEdit` 的坐标映射。净化文件名包含源文件内容 SHA-256，保存前后再次检查源内容，连续重裁时旧任务不能覆盖新版本。副本丢失、不匹配或无法复用时，回退为处理最终裁剪原图；仍失败就保留原图。读取器只匹配当前源内容，进程重启后无需内存任务状态即可找到净化图；文件扫描和哈希均在 IO 线程进行。

不可变副本沿用照片目录的 24 小时无引用文件清理规则，完成交接后删除副本及其净化图。任务取消时保留副本，供 WorkManager 重试使用；取消裁剪不会发布原图路径的展示更新，尚未消费的副本由清理器回收。副本的后台写入不通知界面，最终原图版本发布后只通知对应照片。刷新标识统一 Android 主用户私有目录 `/data/user/0/` 与 `/data/data/` 的等价路径，避免后台任务使用规范路径、界面监听原路径时漏更新；主线程的标识查询不执行文件 IO。

待发缩略图、裁剪和模型附件保持原图；已发送照片、历史封面、题册照片及全屏查看器优先读匹配的净化文件。替换期间保留旧位图，不闪空白，不重置查看器缩放。附件清理器随原图引用保留净化文件，原图无引用且超过宽限期时一并回收。关闭预处理只阻止新任务，不删除已完成的净化文件。

不透明照片的裁剪/旋转保存复用数据层 `StreamingPngWriter`，使用低压缩率的 PNG 编码及逐行缓冲，减少编码计算并避免 OpenCV 冷启动和原尺寸 native 像素副本；透明附件保留系统 PNG 编码，避免改变 alpha 语义。原尺寸、RGB 像素和原子写入规则不变，文件可能比高压缩 PNG 大。长图导出复用同一编码器，继续使用默认压缩级别。

`WarmPaperShadowModel` 是接入后的独立修正：原有空间色偏平滑会在明暗交界混入亮纸颜色，残留橙黄色条带。新模块只在小尺寸的去字背景上，按亮度统计暖色纸张的通道衰减，以较高分位数排除印刷色块，再修正阴影光照场。均匀暖纸、黑板、孤立色斑或证据不足时不启用。它不改变原图笔画，不重绘字符；彩色底框与背面透字的区分仍有局限，不承诺删除所有背景内容。

书页展平主要依赖纵向分布的多组彩色矩形边框及可信文字基线；没有这些结构时保留原有几何，仍可净化背景。它不能恢复被遮住、失焦或严重折叠的内容，也不生成或重绘字符。

文字清晰度修正：原来的强对比曲线（幂指数 2.2）、双边平滑与区域墨色增益会把笔画边缘压黑，背面透字也随之加重。现改用独立的 `DocumentInkTone`，采用温和的边缘曲线；原始像素不做平滑或形态学处理。分条计算的邻域最暗值只用作笔画支撑掩膜：缺少深色笔画支撑的浅灰痕迹会淡化，真实深色笔画附近的灰阶边缘与有色印刷保留。条带带有与邻域半径一致的重叠行，避免边界断线。淡铅笔、浅灰图示与透字不能总是可靠区分，重叠正文处仍采用保守处理。

有损 JPEG 即使设为质量 100 也会重新量化，因此所有照片编辑结果统一写入 PNG，再原子替换；路径保持不变，读取和导出按实际文件头识别类型。设备不足以容纳原尺寸编辑时，预处理保留原文件；裁剪保存失败时留在裁剪界面，不能静默降采样。几何输出完成后立即回收原始位图，净化仍分条执行以降低峰值内存。上传给模型的协议编码与显示预览独立，本次没有调整模型输入大小策略。

裁剪手势：双指缩小照片时，选框与照片共用同一缩放和平移，保持选中的原图区域；选框超出视口边缘时，整体平移回可操作区域，不截短或重新选择内容。同一次缩小手势中的平移、轻微反向放大，以及先松开一根手指后的剩余拖动仍保持联动；放大超过选框顶满视口的大小时恢复原有照片放大操作。手势中心使用上一帧位置，平移量只计算一次。未达到全图重置阈值时，双指微调松手后保留照片与选框的显示大小和位置，点按也不触发顶满；下次实际移动选框或调整边角后，才用 180 ms 动画重新顶满。整张照片恰好完整可见时仍保留原选区，再缩小约 10%（全图适配比例的 0.9 倍）才恢复全图选区；继续缩小仍跟手，松手后用 120 ms 连贯动画回到宽或高顶满。再次触摸可中断适配动画，点按松手后继续；双指微调则取消选框适配。系统关闭动画时，只有需要顶满的操作才立即适配，不改变微调后保持大小的规则。

裁剪框四边使用同一个固定屏幕宽度的矩形描边（外层 4dp、主题色线 1.25dp），不随照片缩放。窄框的角手柄按短边缩小，边中手柄按可用边长缩短；不足以保留间隔时省去短边的中间手柄，密集方向的三等分网格同时省去，避免叠成粗边。手柄的 30dp 触控半径保持不变。

最新的裁剪适配改为占可用视口的 94%，两侧各留约 3% 操作空间，初始全图选区和松手适配使用同一比例。单指向外拉手柄到可视边界后，还需继续外拉超过该轴视口尺寸的 3%，才按停留时间缓慢缩小照片以露出隐藏内容；超过缓冲后的 24dp 内渐进增加速度。边界以内和 3% 缓冲内的普通调框均不触发自动缩小；拉回缓冲内、松手、转为双指操作或取消手势即停止。缩放以未拖动的对边中点或对角为锚点，仅改变正在操作的选区边界，其他边界对应的原图位置保持不变；到照片真实边缘后不再缩小。双指微调后保留大小、再次调整框才适配的规则不变。几何边界、留白、持续外拉、松手停止、双指与宽屏/深浅主题绘制由相关回归覆盖。

## 单张照片的 CPU 并行计算

`PhotoPixelWork` 将原尺寸条带中的通道校正和墨色净化分别分段执行，默认使用可用核数减一、最多 3 个 CPU 工作线程；每段至少 32,768 像素，较小条带和单/双核设备直接串行。后台仍通过原有互斥锁限制同时处理的照片数量，继续共用原有条带数组，不增加整幅位图副本。Bitmap 读写及 OpenCV Mat 操作留在调用线程，不并发修改原生对象，也不更改 OpenCV 自身的 TBB 线程设置。

两个像素阶段均等待所有工作线程结束后才复用缓冲；异常和取消也必须完成收敛，之后才允许回收位图和 Mat。裁剪保存优先及取消检查由调用线程在阶段之间执行，不让 CPU 工作线程阻塞等待前台裁剪。模型继续使用裁剪后的原图，后台结果的版本检查、替换和通知保持原有流程。

性能对比使用 MuMu 12-2 / Android 12，临时配置 4 核，在同一测试进程内对两种执行策略分别预热，随后每张照片每种策略各测量 4 次，交替执行顺序。3072 × 4096 照片的净化阶段中位数由 753.5 ms 降到 534.5 ms（减少 29.1%），包括原尺寸解码、净化和 PNG 保存的总耗时由 1814.5 ms 降到 1600 ms（减少 11.8%）。另外三张照片总耗时分别为：暖阴影页 495 → 462.5 ms、印刷页 483 → 458.5 ms、手写页 499 → 483 ms，减少约 3.2%～6.6%。不能将净化阶段收益当作整体收益，也不能据此推断真机耗时、冷启动或功耗。

四张实拍照片的串行/并行输出，以及并行输出与改动前版本，逐像素一致。性能测试通过可注入的执行策略比较同一套算法，不保留旧算法副本或正式设置开关；照片与详细记录仅在忽略目录 `release-output/photo-detail/cpu/` 和模拟器私有目录中保存。
