# 题目图像预处理

设置中的“题目图像预处理”默认开启；开启后，新解题照片在用户确认裁剪后进入后台净化，不检测是否为题目。添加照片直接打开原有裁剪界面，不等待预处理。对话模式直接跳过，历史图片不做迁移或批量重处理。

当前流程：导入/拍照 → 手动裁剪确认 → 原图加入待发列表，同时由 `QuestionPhotoPreparation` 注册 WorkManager 任务 → `QuestionPhotoPreprocessor` 检查设置、串行净化 → 原子保存独立 PNG → 已发送照片与查看器自动替换显示。发送不等待后台任务；净化未完成或失败时继续显示裁剪后的原图。模型请求、上下文和重试始终使用裁剪后的原图，不读取净化文件。

`BookPageProcessor` 已移除自动书页展平、透视和边界校正入口，只保留 `ColorDocumentEnhancer` 的颜色、背景与阴影净化。手动裁剪/旋转继续保留；原始分辨率与无损 PNG 保存不变。净化全程在本机执行，不请求模型或网络服务。原生库加载失败、内存不足或保存失败保留原文件；取消异常继续抛出。

任务注册由应用作用域持有，离开页面不取消；WorkManager 持久化已注册任务以便进程重启后恢复。相同路径与相同内容使用唯一任务，拍照页到对话页交接不会重复启动仍在运行的任务，已有结果直接复用；原生净化通过互斥锁串行执行，限制多张照片的峰值内存。净化文件名包含源文件内容 SHA-256，保存前后再次检查源内容，防止重新裁剪期间的旧任务发布过期结果。读取器只匹配当前源内容，进程重启后无需内存任务状态即可找到净化图；文件扫描和哈希均在 IO 线程进行。

待发缩略图、裁剪和模型附件保持原图；已发送照片、历史封面、题册照片及全屏查看器优先读匹配的净化文件。替换期间保留旧位图，不闪空白，不重置查看器缩放。附件清理器随原图引用保留净化文件，原图无引用且超过宽限期时一并回收。关闭预处理只阻止新任务，不删除已完成的净化文件。

本轮验证：JDK 21 / Gradle Wrapper 下 92 项相关单元测试、`lintDebug`（0 错误）、`assembleDebug` 和 `assembleDebugAndroidTest` 通过；MuMu 12-2（ADB `127.0.0.1:16448`，Android 12）8 项设备测试通过。覆盖裁剪前不等待、裁剪确认后的任务交接、对话/设置绕过、模型仍读取原图、后台替换显示、相同内容去重、同长度/时间戳的重新裁剪、渲染期间源变化、取消和失败回退、净化文件回收，以及实际 WorkManager/Hilt 执行、原分辨率、阴影、笔画边缘、细线和彩色内容。更新按照片分别通知，避免多张图逐个完成时反复解码整批照片。日志保存在忽略目录 `release-output/photo-detail/background-{validation,device}.log`。正式发布由标签工作流另行执行完整单元测试、Release Lint 和签名构建；真机耗时、息屏和厂商省电行为尚未实机验证，未执行真实进程终止/重启测试。

## 历史优化与测量记录

以下记录针对此前各轮实现；其中自动几何阶段与裁剪前阻塞处理已由上述流程取代。`imaging/book` 最初移植自本机“纸间扫描”项目 `F:/全能扫描王/app/src/main/java/cn/paperscan/app/imaging`。通用几何工具保留供现有独立测试使用，不再由题目照片预处理调用。

`WarmPaperShadowModel` 是接入后的独立修正：原有空间色偏平滑会在明暗交界混入亮纸颜色，残留橙黄色条带。新模块只在小尺寸的去字背景上，按亮度统计暖色纸张的通道衰减，以较高分位数排除印刷色块，再修正阴影光照场。均匀暖纸、黑板、孤立色斑或证据不足时不启用。它不改变原图笔画，不重绘字符；彩色底框与背面透字的区分仍有局限，不承诺删除所有背景内容。

书页展平主要依赖纵向分布的多组彩色矩形边框及可信文字基线；没有这些结构时保留原有几何，仍可净化背景。它不能恢复被遮住、失焦或严重折叠的内容，也不生成或重绘字符。

已发送照片使用独立的 `QuestionPhoto` 完整比例展示，保留点击查看原图；输入框、相机确认条及题册封面继续使用紧凑缩略图。标题栏通过无额外读屏动作的触摸屏障阻挡下方照片，子按钮优先接收事件。

验证：JDK 21 / Gradle Wrapper 下，21 项相关单元测试、`lintDebug`（0 错误）、`assembleDebug` 和 `assembleDebugAndroidTest` 均通过。MuMu 12-2（`MuMuPlayer-12.0-2`，ADB `127.0.0.1:16448`，Android 12 / x86_64）6 项设备测试全部通过，覆盖解题模式无条件处理、开关及对话模式绕过、真实书页、暖色阴影及彩色印刷/细线保留、普通文本/黑板回退和弯曲边框校正。测试照片及输出仅留在本机，不纳入源码。

同一张 1706 × 1279 原图在上述模拟器上的单次阶段测量：0.5.2 题目识别 23,575 ms、处理 5,944 ms、保存 106 ms，共 29,625 ms；新流程处理 4,846 ms、保存 108 ms，共 4,954 ms，减少约 83%。输出仍为 1706 × 1279。对比结果和数值位于忽略目录 `release-output/shadow-preprocessing/shadow-before.*` 与 `shadow-direct.*`。该耗时仅代表这张照片和此模拟器环境，不代表真机性能；真机拍照、息屏及厂商省电行为尚未验证。

文字清晰度修正：原来的强对比曲线（幂指数 2.2）、双边平滑与区域墨色增益会把笔画边缘压黑，背面透字也随之加重。现改用独立的 `DocumentInkTone`，采用温和的边缘曲线；原始像素不做平滑或形态学处理。分条计算的邻域最暗值只用作笔画支撑掩膜：缺少深色笔画支撑的浅灰痕迹会淡化，真实深色笔画附近的灰阶边缘与有色印刷保留。条带带有与邻域半径一致的重叠行，避免边界断线。淡铅笔、浅灰图示与透字不能总是可靠区分，重叠正文处仍采用保守处理。

有损 JPEG 即使设为质量 100 也会重新量化，因此所有照片编辑结果统一写入 PNG，再原子替换；路径保持不变，读取和导出按实际文件头识别类型。设备不足以容纳原尺寸编辑时，预处理保留原文件；裁剪保存失败时留在裁剪界面，不能静默降采样。几何输出完成后立即回收原始位图，净化仍分条执行以降低峰值内存。上传给模型的协议编码与显示预览独立，本次没有调整模型输入大小策略。

裁剪手势：双指缩小照片时，选框与照片共用同一缩放和平移，保持选中的原图区域；选框超出视口边缘时，整体平移回可操作区域，不截短或重新选择内容。同一次缩小手势中的平移、轻微反向放大，以及先松开一根手指后的剩余拖动仍保持联动；放大超过选框顶满视口的大小时恢复原有照片放大操作。手势中心使用上一帧位置，平移量只计算一次。整张照片恰好完整可见时仍保留原选区，再缩小约 10%（全图适配比例的 0.9 倍）才恢复全图选区；继续缩小仍跟手，松手后使用原有 120 ms 连贯动画回到宽或高顶满，再次触摸可中断。未达到重置阈值就松手时，只恢复原选区的展示大小。系统关闭动画时立即恢复。四边用同一个矩形描边，最外层由 6dp 减到 4dp，主题色线由 2dp 减到 1.25dp，辅助网格同步减细；手柄触控范围保留。

裁剪回归覆盖移动并放大的选框、边缘缩放和平移的原图像素映射、双指到单指的衔接、全图重置余量、动画中断和关闭动画、旋转、横屏居中、浅色/深色照片上的完整手柄及取消/确定操作。30 项相关测试通过；调整重置余量后，受影响的 7 项状态与手势回归再次通过，`lintDebug` 和 `assembleDebug` 通过。界面绘制及手势测试使用 Robolectric，真机触感、息屏和厂商省电行为尚未实机验证。

清晰度回归验证：33 项相关单元测试通过，MuMu 12-2 的原生处理测试覆盖透字淡化、灰阶笔画边缘、单像素细线、条带接缝、彩色底框、原尺寸处理和书页几何。新增 2304 × 2048 页面保留完整像素；原有 3072 × 4096 实拍页也完成原尺寸处理。用户提供的印刷页和手写页的修改前后 PNG 输出及局部对比留在忽略目录 `release-output/photo-detail/`，未提交照片。

性能优化保留原始尺寸及上述净化规则。`BookPhotoWriter` 使用已加载的 OpenCV，以 PNG 压缩等级 1 / RLE 保存不透明的处理结果；只减少编码计算量，不丢弃像素。净化逐像素写入 alpha 255 后将结果标记为不透明，省去 PNG 中冗余的 alpha 通道。透明附件仍交给系统 PNG 编码器；原生编码抛出 OpenCV 异常时，先释放缓冲再回退系统编码。两种编码器共用 `writePhotoFileAtomically` 的临时文件、完整写入检查、同步及原子替换规则，不能用失败或空输出替换原图。

几何阶段在整幅照片无需校正时跳过重采样，但仍返回独立位图，保持调用方的回收约定；书页网格与透视的组合变换中，严格的单位透视矩阵直接保留网格坐标，减少逐像素乘除。普通透视与网格输出共用可复用的条带位图，避免逐条带分配。曲面、倾斜和透视的识别阈值、插值核及净化曲线不变。

性能与保真验证：同一 MuMu 12-2、相同四张照片各运行 3 次，记录原尺寸解码、几何、净化和保存阶段。3072 × 4096 实拍页总耗时中位数由 5262 ms 降到 3888 ms（减少 26.1%），其中保存由 2357 ms 降到 636 ms，文件由 6,078,699 字节减到 5,544,876 字节。1279 × 1706 印刷页由 1089 ms 降到 954 ms，1353 × 1761 手写页由 1307 ms 降到 1120 ms。另一张暖阴影照片包含首次运行/JIT 波动，中位数由 4028 ms 降到 3684 ms，不能用其最后一次 1244 ms 代替总体结果。四张照片的输出逐像素与修改前一致，另验证透明 PNG 往返、原始尺寸、细线、灰影、曲面、设置和对话模式绕过。16 项相关单元测试、11 项设备测试、`lintDebug`、`assembleDebug` 和 `assembleDebugAndroidTest` 通过。阶段记录及原图仅位于忽略目录和模拟器私有目录，结果不代表真机耗时、功耗或峰值内存。

进一步减少净化计算：`DocumentInkTone` 用现有曲线生成 256 × 256 的不透明灰度颜色表（256 KiB），覆盖亮度和邻域墨色的全部组合。仅在原算法的 `chroma == 0` 时使用，跳过重复的净化曲线、通道增益和三通道取整；彩色笔迹及底框仍沿用原计算。表本身不持有位图，不改变几何、分辨率、色彩阈值或文件格式，也不增加并行处理的峰值图像内存。

同样四张照片各 3 次，与上一轮 `speed-final` 比较：12MP 页的净化阶段中位数从 1521 ms 降到 1223 ms（减少 19.6%），总耗时从 3888 ms 降到 3787 ms（减少 2.6%）；印刷页总耗时 954 → 917 ms，手写页 1120 → 1147 ms，暖阴影页 3684 → 3953 ms。后两项总耗时未改善，解码、几何、编码及首次运行/JIT 波动仍影响整条流程，不能把净化阶段的收益作为整体提速比例。四张输出仍与上一轮逐像素一致，17 项相关单元测试（含全部 65,536 种灰度组合）、6 项设备测试、`lintDebug`、`assembleDebug` 和 `assembleDebugAndroidTest` 通过。记录位于忽略目录 `release-output/photo-detail/timing-speed-lookup.json` 和 `speed-lookup-summary.json`。以上性能优化均尚未发版。

在允许轻微画质差异后的进一步优化中，光照模型仍保持长边 720、原有滤波范围及暖阴影/书脊修正规则；完成修正后才把光照场转换为 8 位，再进行原尺寸的双线性插值。`ColorDocumentEnhancer` 用 256 × 256 的通道校正表（256 KiB）替代逐像素除法，并在已有像素数组内保存 8 位校正 RGB，移除原尺寸条带中的四通道浮点数组。光照场和插值条带每通道由 4 字节变为 1 字节；这是部分中间缓冲的节省，不是整个进程峰值内存或功耗的测量。净化曲线、笔画支撑掩膜、几何及输出尺寸不变，仍无损保存 PNG；光照插值和校正 RGB 的取整会带来少量颜色差异，不再保证与上轮逐像素相同。

本轮对比以相同的上一轮未发版代码为基准，在同一个 MuMu 12-2 测试进程内预热后交替执行两种实现，每张照片每种实现各 4 次。包括原尺寸解码、几何、净化和保存的总耗时中位数：12MP 页 4061.5 → 3966.5 ms（减少 2.3%）、印刷页 1003.5 → 917 ms（减少 8.6%）、手写页 1256.5 → 1178 ms（减少 6.2%）、暖阴影页 1126.5 → 1051.5 ms（减少 6.7%）；净化阶段减少约 13%～20%。未修改阶段仍有运行波动，不能把净化收益直接作为整体收益，也不能据此推断首次冷启动或真机耗时。

四张实拍照片相对基准的平均 RGB 通道误差为 0.062～0.110（0～255 标尺），99% 的通道差值不超过 2；印刷页有极少量彩色像素的局部差值达到 20，因此平均误差不能代替局部检查。已按原像素查看细小正文、框图细线、彩色底框和手写笔画，未见明显细节退化。对比实现和照片只保留在忽略目录 `release-output/photo-detail/`，不在正式源集中增加旧算法分支；阶段记录为 `comparison-packed-pipeline.json` 和 `speed-packed-pipeline-summary.json`，像素差记录为 `speed-packed-comparison-summary.json`。

本轮 4 项相关单元测试、7 项 MuMu 12-2 设备测试、`lintDebug`、`assembleDebug` 和 `assembleDebugAndroidTest` 均通过，覆盖阴影净化、灰阶笔画边缘、单像素细线、条带接缝、彩色内容、原尺寸处理、解题模式开关及对话模式绕过。仍未发版；真机处理耗时、息屏和厂商省电行为尚未实机验证。
