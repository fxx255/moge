# 题目图像预处理

仅新拍摄或新选择、尚未裁剪的解题照片进入预处理。对话模式在读取设置、OCR 和解码前直接跳过，历史图片不做迁移或重处理。设置中的“题目图像预处理”默认开启。

流程由 `QuestionPhotoPreprocessor` 编排：本机 ML Kit 中文/拉丁文字识别 → 保守题目特征判断 → 纸间扫描几何校正及书页净化 → 原子保存 → 原有裁剪界面。OCR 仅作为是否处理的依据，不写入模型转写，也不发送网络识别请求。识别不到题目或无法确定时保留原图；检测失败、原生库加载失败、内存不足、保存失败都不能破坏原文件。取消异常继续抛出。多张图片串行处理以限制峰值内存。

`imaging/book` 从本机“纸间扫描”项目 `F:/全能扫描王/app/src/main/java/cn/paperscan/app/imaging` 于 2026-10-20 移植，仅保留 `BOOK_FLATTEN` 所需的几何、边界、彩色净化模块。未引入扫描项目的数据库、页面、文件导入或其他滤镜。输出像素预算沿用墨格现有照片解码预算，避免照搬扫描应用较大的内存开销。

书页展平主要依赖纵向分布的多组彩色矩形边框及可信文字基线；没有这些结构时保留原有几何，仍可净化背景。它不能恢复被遮住、失焦或严重折叠的内容，也不生成或重绘字符。自动页面边界必须包含所有 OCR 文字区域，否则使用完整图片，随后由用户裁剪所需题目。题目检测为本机启发式，可能跳过没有可识别文字的图形题。

已发送照片使用独立的 `QuestionPhoto` 完整比例展示，保留点击查看原图；输入框、相机确认条及题册封面继续使用紧凑缩略图。标题栏通过无额外读屏动作的触摸屏障阻挡下方照片，子按钮优先接收事件。

验证：相关 JVM / Compose 回归、`lintDebug`、`assembleDebug` 和 `assembleDebugAndroidTest` 均通过。MuMu 12-2（`MuMuPlayer-12.0-2`，ADB `127.0.0.1:16448`，Android 12 / x86_64）四项设备测试全部通过，覆盖本机 OCR、开关及对话模式绕过、真实书页、普通文本 / 黑板回退和弯曲边框校正。合成图测得的四条独立基线最大漂移由 `[24, 20, 17, 15]` 像素降至 `[1, 1, 0, 8]` 像素，未观测到的底部边缘保留保守过渡。真实书页结果保存在 `app/build/photo-preprocessing-check/book-result.jpg`，不将用户原始照片纳入仓库。尚未验证真机拍照、息屏和厂商省电行为。
