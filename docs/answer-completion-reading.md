# 流式回答结束时保持阅读位置

## 原因

回答是 LazyColumn 中的单个消息。原先列表只保留消息 ID 和像素偏移；生成结束时移除上方草稿、插入简明答案以及刷新最后的 Markdown，都会改变消息内部的排版，因此相同的消息偏移对应了不同的文字。

## 处理

- `MarkdownReadingPosition` 只在生成期间记录阅读区域上缘的文字行或图表位置。结束、停止和失败时，在绘制前定位相同内容，补偿内部布局变化。
- 每帧绘制前读取 Compose 布局坐标；不能只监听 Compose 的内容重绘，滚动时复用绘制缓存的图层仍可能改变位置。
- 用文字上下文找回阅读行，兼容前插答案和文字分块变化；图表使用现有布局块，表格单元格也可作为文字锚点，不增加包裹层或改变绘制顺序。
- 阅读上缘落在表格留白中时，用完整表格内容标识恢复布局块；前插答案导致表格重建，也能找到原表。出现重复表格歧义时不猜测匹配。
- 补偿的保护计时从完成布局首次准备好后才开始，长表格构建原生单元格的耗时不会提前耗尽恢复窗口。
- 使用 Compose 布局坐标。原生 TextView 的位置到 Compose 绘制时才同步，绘制前读取它可能得到旧位置，导致重复补偿。需要补偿时跳过错位帧，并请求正常的 Android 布局遍历，确保下次绘制前能取得新位置，避免只跳过绘制而使位置迟迟不更新。
- 直接提交滚动差值，不取消现有拖动或惯性；独立记录实际浏览位移，避免把用户的翻阅误当成布局跳动。
- 题目或回答页眉仍在阅读上缘时不固定下方正文。页面隐藏、新增问题或切换分支会使旧锚点失效；边界无法补偿时放行绘制。补偿只覆盖结束附近的短暂排版收敛，不长期锁定滚动位置。
- 展开讲解状态只关联回答 ID，简明答案更新不再让正文自动折叠。

阅读锚点只存在于界面内存，不改变历史位置存储、推理存储或生成任务生命周期。

## 回归覆盖

`AnswerCompletionReadingUiTest` 检查折叠/展开草稿移除、末尾插入答案、黑板主题、失败中断、展开状态、导航恢复和新问题优先级。`ReadingOffsetTest` 检查正文追加、前插答案、重新分块和无匹配内容。

`AnswerCompletionReadingDeviceTest` 在真实 Android 布局上检查完成后的文字坐标及实际绘制帧，并覆盖按住手指继续翻阅和含高公式的答案。设备仅使用 MuMu 12-2；厂商真机的表现需后续反馈。
