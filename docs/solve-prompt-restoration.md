# 解题提示词恢复

## 0.5.9 修改

解题主提示词已从 `v0.5.4`（`8e1e6b0`）提取原文，独立放入 `SolveSystemPrompt`；称呼、解题模式、追问规则和思考强度的措辞也以该版本为准。删除 0.5.8 的 `SolveFigureContract` 改写，测试资源单独保留 0.5.4 原文，实际请求载荷与基线逐字比对。以下旧章节记录的是 0.5.7/0.5.8 当时的改动，不代表当前实现。

### 历史核对与绘图链路

- 0.5.4 之前确实改过提示词：0.3.7 补充通信框图角色，0.3.8 加入编码器模板，0.4.4 加入等比例星座图和判决域规则，0.5.2 调整追问及补图规则。0.5.3、0.5.4 没有进一步修改这些解题提示词；大幅精简发生在 0.5.6。
- 本机保留的官方 0.5.4 APK 的 DEX 字符串与该版本源码的完整主提示词一致，包含 `plots`、`diagrams` 和总 JSON 示例。用户反馈现在旧版也无法出图，因此不能仅以 0.5.6 的精简解释当前故障。
- 只读对照 `F:/APP` 的 lixing：两者都依靠模型返回 JSON 绘图数据并由客户端渲染，并非原生画图工具。lixing 当前工作区新增了 JSON 输出约束，但已发布的 1.1.0 提交中没有这项约束，不能据此断定它就是两款应用实际表现不同的原因。
- `SolveOutputFormat` 补上 Chat Completions 的 `response_format` 和 Responses 的 `text.format`。默认请求 JSON 对象；接口明确声明支持 schema 时使用宽松 schema，保留可选的 `answer`、`plots`、`diagrams`，图形结构仍由现有解析器验证。普通对话、配置探测和图片转写不强制解题 JSON；文档解题共用同一规则。
- 只有生成开始前明确的 HTTP 400/422 格式参数拒绝才能放宽约束；不改动原始输入，不对已开始输出的回答做格式回退重发。鉴权、限流、网络错误和通用错误不触发这项回退。

### 追问缓存

`ModelHistorySnapshot` 使用已准备请求的文本、原图路径和每轮上下文，冻结后续发往模型的历史文本；展示排版更新不会修改已有前缀，重新生成的回答通过 attempt 标识更新。`PromptMessageSequence` 在两种协议和文档路径共用：完整固定规则保持一条系统指令，原时间和模式随各轮用户消息回带，新时间只追加到当前用户轮。

`VisionInputImageStore` 让本轮与历史图片共用同一份 2048 像素、JPEG 95 编码，以源文件内容摘要缓存，并限制缓存目录大小。转写后的题目继续作为文字历史，纯图片轮仍发送非空上下文，避免出现空文本块协议错误。

这只提高相同输入前缀的稳定性。模型/称呼/思考强度变化、历史窗口滑动、超过历史图片预算或原附件丢失时，前缀仍可能改变；供应商是否缓存、命中比例和计费由其服务决定。旧记录没有准备快照时沿用原有兼容行为。

本地验证覆盖实际请求序列、连续三轮补图前缀、图形数据解析、JSON 参数拒绝回退、图片缓存、快照和中断恢复。没有调用用户真实接口，尚未证明实际模型出图已恢复，也未确定唯一根因。构建与测试记录位于本机忽略目录 `release-output/prompt-drawing-final.log`。

使用 JDK 21 和 Gradle Wrapper 完成 129 项相关回归，全部通过；`lintDebug`、`assembleDebug` 和 `git diff --check` 通过。这些修改纳入 0.5.9，正式发布工作流另执行完整单元测试、Release Lint 和签名构建。

## 0.5.7 恢复记录

0.5.6 精简主提示词时，同时把标准解答的四段结构改成了“结构随题型安排”，削弱了完整讲解和内部思考不进入正文的约束。本次以 0.5.5（`3b4783c`）为基准恢复，只去重并缩短过长的字段示例，主提示词较该基准约缩短 13%（源码字符数，非 token 统计）。

- `SolveSystemPrompt` 恢复教师式讲解、条件与题号完整性、明确结论、手机排版和本地图表协议；英语等语言题依据原文、语法及选项说明，计算题与证明题保留必要步骤。
- `SolveMode` 恢复标准解答的“分析 → 分步解答 → 最终答案 → 易错点”和查错模式的逐项核对。分析只简述解题方法，默认不复述题目、不另列已知条件和求解目标；必要条件在相应步骤引用。正文不写内部试探、自我对话或反复验证的草稿。
- `PromptAssembler` 的追问规则简化为“追问、补图或补充条件时，结合前文，围绕本轮问题作答。”不再限制只能补充受影响部分，也不特别强调避免重答整题。用户明确指定正文格式或只要答案时遵循其要求，外层 JSON 协议保留。
- 正常生成和正文恢复使用一致的教学说明要求。普通对话模式仍直接输出正文，不注入解题结构。固定规则与时间、解题模式继续分段，避免模式切换改变稳定前缀。

本次不改变模型参数、协议解析、图片追问上下文或自动续写策略，不靠删除模型正文中的疑似思考片段来掩盖问题。提示词约束不能保证所有供应商和模型都完全遵守；远程模型的实际答题效果需单独观察。

## 提示词范围

- 解题主提示词：学科与语言、条件不足时澄清、题号对应、必要教学步骤、明确答案、内部草稿不进入正文、不主动复述题面。
- 输出排版与协议：Markdown、手机公式分行与短表格；JSON 的主题、最终答案、完整讲解字段及图号锚点。主题概括具体考点，手动修改后的主题由客户端保护。
- 本地图形协议：曲线、频谱、星座图、区域阴影、框图和编码器的字段、语义与正确性约束，占主提示词的大部分篇幅。
- 动态规则：标准解答或查错模式、结合前文围绕本轮追问作答、用户指定正文格式优先、当前时间、可选昵称与思考强度。
- 普通对话使用独立简短提示词，自然回答用户，不套解题四段格式，也不强制 JSON。
- 图片转写使用独立识题提示词，保留题面和手写作答以供后续解题；这不是最终解答中复述题目的要求，因此保留。
- 截断续写与正文恢复各有任务指令，要求接续已有内容、保留必要依据，不复述上一轮正文。

## 0.5.8 绘图协议修复

0.5.7 恢复了字段说明，但总 JSON 示例仅列主题、答案和讲解，没有展示并列的 `plots`、`diagrams` 字段。当前将应用绘图契约与完整示例集中到 `SolveFigureContract`：在主提示前部明确应用可依据结构化数据生成图像，补齐曲线和框图共用图号的完整 JSON 示例，并强调数据不能塞进讲解字符串，也不能用字符画或代码块替代图片。无图回答仍使用原有精简结构。

回归通过两种协议的实际请求载荷、流式响应解析及图形排序验证同一份完整示例，确认曲线表达式、坐标范围、框图节点与连线可供渲染。没有接入原生工具调用，也未据此声称所有远程模型均已实测；本次随 0.5.8 发布。
