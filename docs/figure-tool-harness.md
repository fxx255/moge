# 绘图工具循环（测试包）

本次只提供 debug 测试 APK，版本号和发布渠道不变，不创建 release。

## 请求方式

解题请求使用精简公共提示词和两份短工具声明。普通题目直接流式输出最终 JSON，
不增加分类请求。`get_figure_guide(kind)` 按需提供曲线、极坐标、星座/判决域、
框图或编码器的参数说明。`render_figure(figure_id, type, spec)` 使用原有解析器和
本地渲染器校验并生成 PNG，只返回图号、状态、锚点或具体错误，不把图片和整份规格回传给模型。

工具调用使用 Chat Completions 的 `tool_calls`/`role=tool`，或 Responses 的
`function_call`/`function_call_output`。两种协议都保持正文流式输出，拼接工具参数的
增量不会进入正文。Responses 保留完整 output items 与加密推理；Chat 保留工具轮的
reasoning_content / reasoning_details，供下一次请求校验。图片留在原问题消息中。

文档题目共享这个流式循环，并按附件提供原有文档读取工具与范围说明。普通聊天的
自然语言输出协议保持独立。

## 编号、边界和兼容

- 每次生成最多 4 张工具图，以 figure_id 固定顺序；曲线和框图可交错，失败槽位保留。
- 同图最多 3 次尝试，成功图重复提交相同规格复用结果；修正失败不覆盖最后成功的图。
- 普通题目最多 6 轮工具调用，文档题目最多 24 轮。达到上限后禁用工具，再请求一次最终答案。
- 仅推理或占位回答最多恢复一次，降低思考强度；取消和断流均直接传播，保留已有正文。
- 接口忽略 stream 时原地读取已有 JSON；明确拒绝 stream 参数时才请求非流式响应。
- `/models` 明确声明不支持工具，或首次请求以 400/422 明确拒绝 function tools 时，
  使用完整内联绘图协议。拒绝记录按端点、模型和凭证隔离，内存缓存 10 分钟。
- 鉴权、限流、服务端故障、工具 schema 错误、已开始生成后的失败均不触发协议重发。
- 输出预算等参数的明确拒绝沿用原有有限协商；已接受的参数在工具轮之间复用，
  最终恢复主动降低思考强度时重新校验对应值。

公共教学规则、标题和答案规则只保留一份，工具说明复用兼容协议里的绘图规则。
网络层通过 FigureToolRenderer 接口使用 runtime 提供的实现，不依赖 Compose 或位图组件。
原有图片台账、主题变体、缺图补齐、导出与图号平移继续复用。

## 验证与试用

单元测试覆盖真实请求体、两种协议的分片和重放、按需说明、混合图号、错误修正、
轮次上限、预算协商、兼容回退、取消、断流、文档证据及原图保留。
MuMu 12-2 的设备测试用本地接口夹具生成真实编码器和极坐标 PNG，并验证日夜主题重画。
这些验证不调用用户保存的模型接口。

诊断统计继续逐个 HTTP 请求记录 usage 和缓存 token，整轮耗时与额外请求数包含工具轮。
回答底部改为本次回答的累计输入、缓存输入和输出，包含识题、工具轮、自动续写和补图请求。
同一 HTTP 流的累计 usage 只取最终快照，再跨 HTTP 相加；缓存是输入的子集，推理是输出的子集，
均不重复相加。计数随回答保存，重开会话仍显示累计值。供应商缺失字段显示未知或已知下限；
旧回答仅存过最后一个有用量的请求样本，标为「旧版单次」。手动继续的旧前段未保存用量时，标明前段缺失，
不把新段小计冒充全文总数。
测试限制公共提示词加工具声明的字符数低于旧完整协议的 35%；字符比例不能视作实际 token、
计费或延迟收益。尚未进行真实模型的效果/费用对照，需试用不同模型和题目，比较普通题、
函数图、符号频谱、判决域、通信框图、编码器和文档题。息屏及厂商省电行为仍需真机验证。

## 2026-10-28 计时与绘图等待优化

每次尝试由应用任务持有一个 elapsed-realtime 起点，从提交准备开始计时，包含快照、识题、
所有模型轮次、缺图补齐、PNG 渲染和回答的首次保存事务。回答保存提交后记录完成耗时，
随后按 request / attempt / answer 三重身份补写该值，旧尝试不能覆盖新结果。补写本身与
界面的逐字显现动画不计入生成耗时。重试从本次尝试重新计时。
页眉与草稿共用该起点；出现正文后继续走时，退出页面再回来不会重置，完成后显示保存值。
elapsedRealtime 包含设备休眠时间，不受修改系统时间影响。

工具图先同步完成参数校验，再进入本次 solve 协程作用域内的有界渲染队列，最多两项并行。
后续正文请求可与本地渲染重叠；同图号的修订按提交顺序运行。固定返回 `accepted` 表示
已校验并受理，不因某次渲染快慢改成不同的工具结果，也不冒称渲染已完成。最终返回前
等待本次所有绘图任务，只发布成功规格；失败保留该槽位最后成功的规格，否则保留缺图，
由原有补图流程处理。取消或模型请求失败会取消并收尾本次队列，不留下脱离任务的绘图。
PNG 存储仍复用现有台账、缓存和主题变体；同类图片存储的写锁仍生效。

这一步并发的是本地参数绘图与模型正文，没有新增独立的绘图模型请求。相同规格继续作为
绘图和正文的共同依据。其收益受本地渲染耗时限制；多次模型往返和模型推理仍可能占主要时间。

同一种 guide 首次返回完整说明，重复读取返回前文引用，避免再次追加整份说明。常规工具轮
保持系统提示、工具定义和全部既有消息逐字一致，只追加模型调用、推理重放和工具结果，
包含原问题图片。已有跨追问的逐轮上下文继续沿用，新增回归验证新时间/模式不会改写旧用户消息。
达到轮次上限、恢复空答案、联网首次强制搜索及明确参数协商仍有必要的协议变化，不承诺这些
路径前缀完整一致。历史回答没有保留整轮工具轨迹，跨追问也不声称复用了上一轮全部工具前缀。

本地请求体一致性无法证明供应商实际缓存命中或计费改善。应在相同模型、强度和题目下比较
整次回答的总耗时、HTTP 次数、未缓存输入（输入减缓存输入）与输出，而非只比较命中率。
本次官方缓存文档页面抓取被网络拦截，未添加未经验证的供应商专属缓存参数。
