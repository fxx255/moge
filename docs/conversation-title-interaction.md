# 对话主题栏

已有会话的顶部主题保留荧光笔标题样式。超出可用宽度时，文字完整显示后停留 2 秒，以 18dp/s 缓慢循环展示，循环之间停留 2 秒；短标题静止。文字与荧光笔一起移动，设置等右侧按钮保持固定。系统关闭动画时保留静态省略显示，读屏仍能读取完整主题。

长按已有会话的主题，在同一顶部栏内展开便签纸输入框，沿用日夜主题的便利贴配色，带轻阴影、顶部粘贴带和折角。文字自动换行，去掉三行上限；空间不足时输入区可滚动，保存按钮始终在文字下方。不再显示“对话主题”标题或取消按钮，只在右下角保留对勾。输入框自动获得焦点并请求系统输入法，首次选中原主题便于替换。对勾或键盘完成键保存；点击便签外、返回键取消修改，并隐藏键盘。便签外的取消点击由独立输入层消费，不会触发底层照片、返回按钮或输入栏。保存未完成时不响应重复保存或取消。编辑时隐藏原右侧操作以留足空间，并暂停页面横滑。尚未建立会话时，“新题目 / 新对话”继续用于模式切换。

`ConversationTitleEditor` 只管理交互与草稿，保存经 `SolveViewModel.renameTitle` 回调交给 `ConversationRepository`。主题规范化与 1～80 码点长度规则统一位于 `ConversationName`，不会把 emoji 的 UTF-16 代理对误算为两个字。保存过程中禁止重复提交；失败保留草稿并允许重试。生成期间发生的自动主题更新不替换正在编辑的文字。

手动命名同时持久化 `title_user_edited` 标记，首次或后续模型回答不得覆盖手动主题。Room 6→7 迁移仅增加默认值为 0 的列；已经安装的旧版本保留原主题、消息、分类与题册记录。历史页已有的重命名入口也使用此保护。

## 自动命名

解题模式中，恢复后的主提示词重新要求概括核心考点、避免泛称，并把 `conversation_title` 放在 JSON 的第一个字段；本轮进一步明确 `conversation_title` 和 `reply` 为必填字段。这有助于减少模型省略主题，也便于长回答截断时提取已完成的开头主题，但无法保证所有模型遵循。没有主题时继续保留原首问标题或图片占位标题，不额外请求模型。

普通对话模式使用直接正文协议，仍以首条消息生成初始主题，不要求模型返回 JSON，也没有新增一次独立主题总结请求。
